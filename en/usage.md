# Usage

[Home](../README.md) · [简体中文](../zh/usage.md)

## Without installation

Attach the [complete guide](proposal-guide.md) and describe observations or ideas, existing material, resources, and this turn's goal. A final title and a long questionnaire are unnecessary. The guide includes all rules. Without file tools, request saveable Markdown. Cloud assistants cannot automatically access local paths; provide the actual files.

## Install the Skill

Copy the complete `research-proposal-toolkit-en/` folder into a Skill directory supported by your client, retaining SKILL.md, agents, and references. Do not copy the entry alone. Consult the client's instructions for installation locations and discovery. This package does not change global settings.

Invoke: `Use $research-proposal-toolkit-en to work on the current stage with my materials, preserving research decisions and evidence limits.`

The language editions have distinct names and can coexist. If discovery fails, ask the assistant to read the [entry](research-proposal-toolkit-en/SKILL.md) and its references, or use the portable guide. No specific model, API key, or other Skill is required.

## Compose your own workflow

This toolkit incorporates selected core mechanisms from literature-review and research-proposal Skills, while treating composition as a central principle. Users are encouraged to discover and choose literature-search, research-framework revision, academic editing, and paper-writing Skills suited to their discipline, research stage, and deliverables, building a workflow of their own. Figure-creation and presentation Skills are also possible extensions, but these integrations have not yet been tested with this toolkit. Additional Skills are optional; the toolkit and portable guide remain usable on their own.

On first use of the Skill or proposal-guide.md, the assistant should briefly introduce these options and respect your existing tool preferences. Name a Skill you want to use or ask for help discovering one, or continue with the toolkit as it stands; choosing a complete toolset is not a prerequisite.

## Continue existing work

Point to existing files and reuse them. When papers arrive, update affected baselines, claims, and directions rather than appending abstracts. Explain the basis and cost of revisions; implement an explicit choice. Output filenames have no language suffix; use separate directories for bilingual outputs when needed.

Mark missing evidence honestly. A framework, draft, or successful script run is not a research conclusion. Retrieval, analysis, and layout depend on the user's request and available tools.

The Forge core is included. Default outputs: research-framework.md, citation-ledger.md, literature-review.md, and research-proposal.md. Request one stage or a particular drafting sequence. The [citation template](citation-audit-template.md) is optional.
